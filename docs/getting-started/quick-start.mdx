# Quick start

For the hosted app, follow [plugin setup](/getting-started/hosted). You do not need to deploy anything.

## Deploy your own instance

1. Read the [requirements](/getting-started/requirements). Create your own Convex and WorkOS accounts.
2. Clone the reviewed release. It is currently separate from `main`:

```bash
git clone --branch codex/convex-static-hosting-release https://github.com/waynesutton/opensync.git
cd opensync
npm ci
npx convex dev
```

Select your own Convex project. Keep this terminal running while developing.

3. Set `WORKOS_CLIENT_ID` and the server-side `WORKOS_API_KEY` on your development deployment using the Convex dashboard. Configure callbacks and allowed origins in [WorkOS](/auth/workos).
4. Keep the generated `VITE_CONVEX_URL` in `.env.local`. Add your WorkOS client ID:

```bash
VITE_WORKOS_CLIENT_ID=client_your_client_id
# Leave VITE_REDIRECT_URI unset locally to use the actual Vite port.
```

5. In a second terminal, start the frontend:

```bash
npm run dev
```

Open the exact URL Vite prints. Both `http://localhost:5173/callback` and `http://localhost:5174/callback` must be registered if you use both ports. Register the two origins without `/callback` in the allowed-origins setting.

6. Sign in, generate an API key in Settings and connect a plugin to your own deployment. Do not use the hosted OpenSync API for a private fork.

## Publish the frontend

Follow [Convex static hosting](/hosting/static-hosting) to configure production, deploy backend functions and upload the Vite build. Backend deployment and frontend upload are separate steps.

Optional semantic search requires your own OpenAI key. Email setup is optional and sending stays blocked in test mode. Neither is needed to start reviewing synced sessions.
